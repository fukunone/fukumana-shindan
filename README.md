# フクマナ「福祉経営 学びタイプ診断」

保育博2026のブースやSNSから案内する、スマホ向けの無料診断サイトです。
HTML・CSS・JavaScriptだけで動き、**回答はブラウザの中だけで処理され、どこにも保存・送信されません**。
効果測定のため Googleアナリティクス（GA4）を使っていますが、送るのは「開始・設問への到達・完了・ボタンのクリック」の記録だけで、回答内容は送りません（[8. アクセス解析](#8-アクセス解析googleアナリティクスga4)）。

- 仕様：[SPEC.md](SPEC.md)
- 公開URL：`https://fukunone.github.io/fukumana-shindan/`
  - 保育博用：`https://fukunone.github.io/fukumana-shindan/?field=hoiku&src=hoikuhaku`（Q1「分野」を飛ばして保育として診断）
  - SNS・チラシ用：`https://fukunone.github.io/fukumana-shindan/?src=sns`

## 1. 公開手順（GitHub Pages）

初回だけ、次の手順で設定します。

1. このリポジトリの変更を `main` ブランチに取り込む（プルリクエストをマージ）
2. GitHub のリポジトリ画面 → **Settings** → 左メニュー **Pages**
3. **Build and deployment** の **Source** を **「GitHub Actions」** にする
4. **Actions** タブで「GitHub Pages に公開」が緑のチェックになるまで待つ（2〜3分）
   - 動いていなければ「GitHub Pages に公開」→ **Run workflow** で手動実行
5. Settings → Pages に表示される URL を開いて確認する

以後は `main` に変更が入るたびに自動で公開し直されます（結果ページ・OGP画像・QRコードも自動で作り直されます）。

> **リポジトリが非公開（Private）の場合**：GitHub Pages を使うには、無料プランではリポジトリを公開（Public）にする必要があります（有料プランなら非公開のまま可）。

### 公開URLが予定と違う場合（独自ドメインを使う場合など）

SNSのプレビュー画像（OGP）とQRコードは公開URLをもとに作られます。
`data/content.json` の `site.url` を実際の公開URL（`https://` で始まり `/` で終わる形）に書き換えて `main` に反映してください。

## 2. QRコード

公開後、次のURLからダウンロードできます（`site.url` から自動生成）。

| 用途 | ファイル | 読み取り先 |
|---|---|---|
| 保育博用 | `assets/qr/qr-hoiku.svg`（印刷用）／`.png` | `公開URL?field=hoiku&src=hoikuhaku` |
| SNS・チラシ用 | `assets/qr/qr-sns.svg`（印刷用）／`.png` | `公開URL?src=sns` |

`src=` は、Googleアナリティクスで「どのQRから来たか」を区別するための目印です（[8. アクセス解析](#8-アクセス解析googleアナリティクスga4)）。
SNSの投稿文などにURLを直接貼るときも、`?src=sns` を付けたURLを使うと区別できます（例：Instagramのプロフィール用に `?src=instagram` のように新しい目印を作ることもできます。半角英小文字・数字・ハイフン・アンダーバーのみ）。

例：`https://fukunone.github.io/fukumana-shindan/assets/qr/qr-hoiku.svg`

**印刷前に必ず、スマホで読み取って診断ページが開くことを確認してください。**

手元のパソコンで作る場合（Node.js が必要）：

```bash
npm install
```

```bash
npm run build
```

### 配色

**基本色**（背景・ボタン・フッターなど）は、ロゴ（濃い青緑 `#005660`・青緑 `#00979f`）とフクノネコ（青緑 `#00aab2`）の色を基準にしています。
文字に使う色は、背景とのコントラスト比（文字の読みやすさの指標。4.5以上が目安）が4.5以上になるようにしています。`npm test` で自動チェックされます。

**タイプの色**は、MBTIのように色の系統で立場が分かるよう、4つのグループに分けています（`data/content.json` の `groups` と各タイプの `group`）。

| グループ（立場） | 系統 | タイプ（文字・帯の色 ／ 飾りの色） |
|---|---|---|
| 現場で輝くグループ（一般職員） | オレンジ | 現場リーダー候補 `#c2410c`／`#f97316`・未来の経営者 `#9a3412`／`#ea7a3c`・現場のプロフェッショナル `#b45309`／`#f59e0b` |
| チームをつなぐグループ（管理職） | 紫 | チームを育てる中核人財 `#8b3fbf`／`#c084fc`・経営視点を磨くマネージャー `#5b2a86`／`#9b6dc6` |
| 法人を導くグループ（経営者・役員） | 紺 | 組織を育てる経営者 `#2c4f9e`／`#6b8fe0`・経営基盤を固める経営者 `#16285c`／`#4a64a3`・選ばれる法人をつくる経営者 `#1e5aa8`／`#5aa0e6`・経営全体を見渡す経営者 `#2a4a6b`／`#7f9fbf` |
| 未来をひらくグループ（開業検討） | ゴールド | 開業準備 `#8a6500`／`#e3b23c` |

- `color`（文字・帯）：結果画面とシェア画像のタイプ名の文字、上部の帯。白とのコントラスト比4.5以上が必要です（ゴールド・オレンジは濃いめ）。
- `accent`（飾り）：伸びしろ分野のタグ、区切り線、背景の円。明るい色で系統が分かるようにしています。
- グループ名（`groups` の `name`）は画面には表示しません。シェアページの「診断でわかる10のタイプ」（数は自動）では、見出しを付けずにグループごとにまとめて並べ、グループの間に余白を空け、各タイプをグループの色で示しています。
- フクノネコ本体の色は変えていません。

変更する場所：
- 基本色：`css/style.css` の先頭（`:root { ... }`）
- グループ・タイプの色：`data/content.json` の `groups` と各タイプの `color` / `accent`
- 結果画像・OGPの背景や文字の色：`js/card.js` の `THEME`

## 4. 文言の編集（質問・結果・リンク）

**文言はすべて `data/content.json` の1ファイルにまとまっています。**
GitHub 上でファイルを開き、鉛筆アイコン（Edit）から直接編集できます。

| 変えたいもの | 場所 |
|---|---|
| トップ画面の説明 | `top` |
| 分野ごとの呼び方（園／事業所・施設…） | `fields` の `place`（場所）・`staff`（職員の呼び方）・`roleNotes`（立場の補足） |
| 質問と選択肢 | `roles` → `A`（一般職員）`B`（管理職）`C`（経営者）`D`（開業検討）→ `questions` |
| 講義の名前・1行説明・伸びしろ分野名 | `courses` |
| タイプ名・キャッチコピー・説明文・次の一歩ボタン | `types` |
| 学び方アドバイス | `advice`（共通）と各 `roles` の `advice` |
| リンク先URL | `links`（**仕様で固定。変更しないでください**） |

### 書き方のルール

- 文字は `"` と `"` の間だけを書き換えてください。`"`・`,`・`{` `}` を消すと動かなくなります。
- `{place}` は分野に応じて「園／事業所・施設／職場」、`{staff}` は「保育士／職員」に自動で置き換わります。
- `{br}` は「スマホで折り返すならここで」という改行位置の目印です。画面・シェア文・画像には表示されません。質問文・選択肢・キャッチコピーで使えます。
  例：`"今いちばん{br}伸ばしたい力は？最も近いものを{br}1つ選んでください"` → スマホでは「今いちばん／伸ばしたい力は？／最も近いものを／1つ選んでください」と折り返します（画面が広いときは1〜2行のまま）。
  読点「、」と「？」の後ろは、目印がなくても改行位置になります。
- 選択肢の `"scores": { "finance": 3 }` は「この選択肢を選ぶと『財務・会計』に3点」という意味です。
  講義の記号：`finance` 財務・会計／`tax` 税務／`labor` 労務／`management` マネジメント／`kaigyo` 開業／`analysis` 内部統制・経営分析／`marketing` マーケティング／`sp1` 特別講義1／`sp2` 特別講義2／`sp3` 特別講義3
- 表現ルール（仕様書2章）：営利的な表現は使わず「収支差額」「本業の収支」など／料金・価格は書かない／制度名・数値は書かない／「弱み」ではなく「伸びしろ」。

保存（Commit）すると自動でチェックが走り、書き間違いや禁止表現があると **Actions タブが赤く** なって公開が止まります（サイトは直前の正常な状態のまま）。赤いときは中のログに理由が日本語で表示されます。

### 診断のしくみ（参考）

1. 立場ごとの質問で、選んだ選択肢の点数を各講義に足します。
2. 点数の高い順に3講義を「おすすめの講義」として表示します（同点は `priority` の順）。
3. タイプは次のように決まります（`typeRule`）。
   - 一般職員：Q「将来の働き方」の答えで決定。開業志向は「開業」「財務・会計」を必ずおすすめに含めます。
   - 管理職：最後の質問「今いちばん伸ばしたい力は？」の答えで決定（`typeRule.map`）。
     選んだ力に対応する講義（選択肢の `ensureCourses`。例：「職員一人ひとりを育てる力」なら特別講義3）が、おすすめ講義に必ず1件以上入ります。
   - 経営者・役員：最後の質問「今いちばん優先したい課題は？」の答えで決定（`typeRule.map`）。「上記以外の課題がある」は「経営全体を見渡す経営者タイプ」になります。
     選んだ課題に対応する講義（選択肢の `ensureCourses`。例：「必要な職員を採用すること」なら特別講義2）が、おすすめ講義に必ず1件以上入ります。入っていない場合は、点数上位3件のうち順位がいちばん低い講義と入れ替えます。
   - 開業検討：常に「開業準備タイプ」。開業時期で説明文が変わります。
   - タイプは必ず本人が選んだ答え（`"by": "tag"`）か固定（`"by": "fixed"`）で決まり、点数の同点で決まることはありません（`npm test` で全回答パターンを確認）。

## 8. アクセス解析（Googleアナリティクス・GA4）

- 測定ID：`G-GTDPRT5SN9`（`data/content.json` の `analytics.measurementId`。空 `""` にすると止まります）
- 手元のパソコン（`npm run serve` など）で開いたときは送信しません。公開サイトのアクセスだけが記録されます。
- 画面のフッターに「Googleアナリティクスを使用しています。診断の回答内容は送信しません。」と表示しています。

### 送っている記録（イベント）

| イベント名 | いつ | 一緒に送る項目 |
|---|---|---|
| `page_view` | ページを開いたとき（GA4の標準） | ページのURL（`?src=` は「参照元」として記録） |
| `diagnosis_start` | 「診断をはじめる」「もう一度診断する」を押したとき | なし |
| `question_reach` | 各設問が初めて表示されたとき（「戻る」で同じ設問に戻っても数えない） | `question_number`：設問の番号（1, 2, 3 …） |
| `diagnosis_complete` | 結果が表示されたとき（1回の診断につき1回） | `role_id`：立場（A 一般職員／B 管理職／C 経営者・役員／D 開業検討）、`type_id`：タイプ（例 `core`） |
| `cta_click` | 「次の一歩」のボタンを押したとき | `link_type`：`line`（公式LINE）／`company`（法人フォーム）／`keiei`（経営コース）、`type_id` |
| `share_click` | シェアのボタンを押したとき | `share_method`：`x`／`line`／`copy_link`（リンクをコピー）／`save_image`（結果画像を保存）、`type_id` |

**送らないもの**：分野の答え、各設問で選んだ選択肢、おすすめ講義、伸びしろ分野など、回答の内容は一切送りません（`npm run e2e` で確認しています）。

- `question_number` は「何問目まで進んだか」です。保育博用QR（分野の質問なし）は Q1 が「立場」、それ以外は Q1 が「分野」・Q2 が「立場」です。立場によって設問数が違います（保育博用QRの場合：一般職員・管理職 7問、経営者 8問、開業検討 6問）。
- GA4 は上の表のほかに、`session_start`（訪問の始まり）・`first_visit`（初めての訪問）・`user_engagement`（ページを見ていた時間）を自動で記録します。回答内容は含まれません。

#### 最初に1回だけ行う設定（GA4の管理画面）

1. **拡張計測機能を最小にする**
   [管理（左下の歯車）] → [データの収集と修正] → [データストリーム] → ストリームを選ぶ → [拡張計測機能] の歯車。
   「ページビュー数」だけをオンにし、「スクロール数」「離脱クリック」「サイト内検索」「動画エンゲージメント」「ファイルのダウンロード」「フォームの操作」はオフにして保存します。
   （オンのままだと、上の表にない記録が増えます。回答内容が送られることはありません）
2. **項目（パラメータ）をレポートで使えるようにする**（カスタムディメンション）
   [管理] → [データの表示] → [カスタム定義] → [カスタムディメンションを作成] で、次の5つを1つずつ作ります。範囲はすべて「イベント」です。

   | ディメンション名（自由） | イベントパラメータ（正確に入力） |
   |---|---|
   | 設問番号 | `question_number` |
   | 立場 | `role_id` |
   | タイプ | `type_id` |
   | ボタンの種類 | `link_type` |
   | シェア方法 | `share_method` |

   ※作成した日以降のデータから使えます。保育博（11/19）の**前までに**作成してください。反映まで最大24〜48時間かかります。
3. **キーイベント（成果）を設定する**
   [管理] → [データの表示] → [イベント] で、`cta_click` の行の「キーイベントとしてマーク」をオンにします（`diagnosis_complete` もオンにしておくと便利です）。
   ※イベントが一度も記録されていないと一覧に出ません。公開後に自分で一度診断し、ボタンを押してから設定してください。

### 数値の見方

左のメニュー [レポート] から確認します。画面右上の日付で期間（例：保育博の 2026/11/19〜11/20）を指定してください。

| 知りたいこと | 見る場所 |
|---|---|
| **今まさに使われているか**（当日のブースで確認） | [レポート] → [リアルタイムの概要]。「イベント数（イベント名）」に `diagnosis_start` などが出ます。自分でQRを読んで診断すると数十秒で表示されます |
| **保育博のQRから何人来たか** | [レポート] → [集客] → [トラフィック獲得]。表の左上の項目名を「セッションの参照元 / メディア」に変え、`hoikuhaku / qr`（保育博）、`sns / qr`（SNS用）の行を見ます |
| **診断を始めた数・終えた数・ボタンを押した数** | [レポート] → [エンゲージメント] → [イベント]。`diagnosis_start`（開始）、`diagnosis_complete`（完了）、`cta_click`（次の一歩）、`share_click`（シェア）の「イベント数」を見ます |
| **どの立場・タイプが多いか** | [イベント] で `diagnosis_complete` をクリック → 「立場」「タイプ」のカードを見ます（上の設定2が必要） |
| **LINE・法人フォーム・経営コースのどれが押されたか** | [イベント] で `cta_click` をクリック → 「ボタンの種類」のカード（`line`／`company`／`keiei`） |
| **何問目で離脱しているか** | [イベント] で `question_reach` をクリック → 「設問番号」のカードで、番号ごとの数を比べます（数が大きく減る番号が離脱の多い設問） |

#### 保育博からの流れだけを見る（ファネル）

1. 左のメニュー [探索] → [ファネルデータ探索] を開きます。
2. 左の「セグメント」の「＋」→ [セッション セグメント] → 条件に「セッションの参照元」＝`hoikuhaku` を指定して保存し、右の「セグメントの比較」にドラッグします。
3. 「ステップ」の鉛筆アイコンから、次のステップを作ります。
   1. 開始：イベント名 ＝ `diagnosis_start`
   2. 完了：イベント名 ＝ `diagnosis_complete`
   3. 次の一歩：イベント名 ＝ `cta_click`
4. 開始 → 完了 → ボタンのクリックまで、何人が進んだか（何%残ったか）が表で表示されます。

**数え方の注意**
- 同じ人が「もう一度診断する」を押すと、開始・完了がもう1回数えられます。人数で見たいときは「イベント数」ではなく「総ユーザー数」の列を見てください。
- 広告ブロックやブラウザの設定で計測を拒否している人は記録されません。実際の利用者数より少し少なめに出ます。
- 保育博用QRで来た人がその場で結果をシェアし、それを見た人が来た場合は、参照元は `hoikuhaku` ではなく `t.co`（X）や `line` などになります。

## 9. 会場の電波対策

展示会場は電波が混み合うため、次の対策をしています。

### トップ画面を軽く・早く表示する

| 対策 | 内容 |
|---|---|
| トップ画面をHTMLに書き出す | JavaScript や文言ファイルの読み込みを待たずに表示します（`npm run build` が `data/content.json` から自動で書き出し） |
| 見た目（CSS）とトップのフクノネコを埋め込む | 通信の往復を減らします（`css/style.css` を編集したら `npm run build`。公開時は自動） |
| 画像を軽くする | 画面用の画像を縮小して WebP にしています（`assets/opt/`、自動生成。1枚 約42KB → 約17KB）。WebP を表示できない古い端末では元の PNG を使います |
| 必要になるまで読み込まない | フォントはトップ画面の表示後、結果画像の描画プログラム（`js/card.js`）は「診断をはじめる」を押した後、Googleアナリティクスはページの読み込み後に読み込みます |

計測（`npm run perf`。Slow 3G 相当：1回の通信ごとに2秒の遅延・毎秒約50KB）：

| | 改善前 | 改善後 |
|---|---|---|
| 最初の表示 | 6.2秒 | 2.5秒 |
| トップ画面の表示（診断名・ボタン・フクノネコ） | 13.1秒 | 2.5秒 |
| 「診断をはじめる」が使えるまで | 8.5秒 | 4.8秒 |
| トップ画面の表示までの通信量 | 283KB | 45KB |
| 2回目に開いたとき | 2.2秒 | 0.04秒 |

※ 手元での計測です。Googleアナリティクスは含みません。改善後はアナリティクスの読み込みを後回しにしているため、本番でもトップ画面の表示には影響しません。
※ JavaScript の読み込み中に「診断をはじめる」を押した場合は「準備中…」と表示し、読み込みが終わり次第そのまま始まります。

### 一度開けば、電波が切れても最後まで

- トップ画面を開くと、Service Worker（`sw.js`）が診断に必要なファイル（画面・文言・画像・結果画像の描画）を端末に保存します。
- その後に電波が切れても、診断を最後まで進め、結果画面の表示と結果画像の保存までできます（`npm run e2e` の [8] で、サーバーを止めた状態で確認しています）。
- 電波がないときに LINE・法人フォーム・経営コース・Xでシェア・LINEで送るのボタンを押すと、ページを開かずに「電波が戻ったら、もう一度押してください」と案内します（文言は `data/content.json` の `offline.message`）。
- フォントは一度表示に使った分だけ保存します。電波がないときに保存されていない文字は端末のフォントで表示されます（結果画像も同じ）。
- 端末が「電波なし」と判断していない状態（電波が極端に弱いだけの状態）では、案内が出ずにボタンのページを開こうとします。

### サイトを更新したとき

- `npm run build`（公開時は自動）で、保存するファイルの中身から版（`sw.js` の `VERSION`）を作り直します。ファイルが1文字でも変わると版が変わります。
- 更新後に利用者が次に開いたとき、新しい版を保存して切り替わり、古い保存は削除されます。トップ画面にいるときはすぐに新しい版で開き直し、診断の途中なら中断せずに、次に開いたときから新しい版になります（`npm run e2e` の [10] で確認）。
- `sw.js` の `PRECACHE` の部分は手で編集しないでください。

## 10. 保育博ブース用の印刷物

`npm run print` で `print/pdf/` に作成します（見本画像は `print/preview/`）。QRコードはすべて保育博用（`公開URL?field=hoiku&src=hoikuhaku`）です。

| ファイル | 内容 | 用途 |
|---|---|---|
| `pop-a4_home.pdf` | 卓上POP A4縦（周りに8mmの余白） | 家庭・事務所のプリンター（「実際のサイズ」「100%」で印刷） |
| `pop-a4_press.pdf` | 卓上POP A4縦（仕上がり210×297mm・塗り足し3mm・トンボ付き、用紙240×327mm） | 印刷会社への入稿 |
| `qr-card_a4-10up.pdf` | QRカード 91×55mm をA4に10面付け（1ページ目＝表、2ページ目＝裏） | 市販の名刺用紙（A4・10面、上下11mm・左右14mm）。両面印刷は「長辺とじ」 |
| `qr-card_press.pdf` | QRカード（仕上がり91×55mm・塗り足し3mm・トンボ付き、1ページ目＝表、2ページ目＝裏） | 印刷会社への入稿 |

- POPのQRコードは112mm（家庭用は103mm）。読み取る距離の1/10という目安（1mなら10cm）を満たしています。作成時に、スマホのカメラ（フルHD）で離れて写したときの粗さまで画像を縮小・ぼかして読み取れるか確認しています（POP：2mまで、カード：0.5mまで読み取り可）。
- 写真・イラストは印刷サイズで350dpi以上（実際は約750dpi以上）。文字はフォント埋め込み、QRコードは図形（ベクター）です。
- 色はRGBです。印刷会社によってはCMYKへの変換で色味が少し変わります（入稿時に「RGB入稿可」か確認してください）。
- 作成時に、価格・料金、制度・統計、営利的な表現が入っていないかを自動で確認します。
- **印刷したら、実物をスマホで1m離れて読み取れることを確認してください。**
